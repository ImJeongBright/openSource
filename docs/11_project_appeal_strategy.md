# 공모전 어필 포인트 및 차별화 전략 (Pitch Strategy)

본 프로젝트가 심사위원들에게 어떻게 강력하게 어필할 수 있는지, 남들과 어떤 점이 다르며, 왜 '기본기에 충실한 훌륭한 엔지니어링'인지를 강조하기 위한 전략입니다. 발표 자료(PT)나 심사위원 질의응답 시 핵심 무기로 활용할 수 있습니다.

---

## 1. 남들과의 확실한 차별점 (Differentiation)

**🚫 일반적인 참가자들의 접근 방식 ("블록 조립형")**
* 대부분의 참가자는 LangChain, LlamaIndex 같은 무거운 AI 프레임워크에 Pinecone, Milvus 같은 외부 Vector DB를 단순히 연결하여 '돌아가기만 하는 챗봇 데모'를 가져옵니다.
* 데이터가 어떻게 흘러가고 예외 상황에서 어떻게 복구되는지(Data Engineering)에 대한 고민이 부족합니다.

**✅ 우리의 접근 방식 ("Full-Control 엔지니어링")**
* **순수 DB 중심 아키텍처**: 외부 Vector DB나 메시지 큐(RabbitMQ, Redis 등)를 일절 쓰지 않고, 오직 **OpenSQL(PostgreSQL) 하나만으로 모든 것을 해결**했습니다. 관계형 데이터(문서 이력)와 비정형 데이터(임베딩 벡터), 그리고 비동기 큐(Queue) 처리까지 단일 데이터베이스의 기능을 극한으로 활용합니다.
* **프레임워크 종속성 탈피**: RAG 파이프라인의 핵심인 청킹, 임베딩 적재, 상태 관리를 블랙박스 프레임워크에 의존하지 않고 바닥부터(From scratch) 직접 설계하여 시스템 장악력을 증명합니다.

## 2. 기본기에 충실함 (Back to Basics & Robustness)

심사위원(특히 시니어 엔지니어)들은 화려한 AI 결과물보다 **"서버가 죽었을 때 데이터가 무사한가?"**를 봅니다. 이 프로젝트는 철저히 백엔드 기본기에 집중합니다.

* **완벽한 트랜잭션 (ACID) 보장**
  * 여러 테이블(`documents`, `versions`, `change_log`)에 들어가는 데이터를 하나의 **Atomic INSERT**로 묶고, 파이프라인 처리가 완전히 끝나야만 `activate_version()` 저장 함수를 통해 기존 문서를 덮어씁니다. 
  * "검색 중에 데이터가 절반만 업데이트되는 일"을 원천 차단합니다.
* **DB 기능의 스마트한 활용 (동시성 제어)**
  * 추가적인 인프라(Kafka 등) 없이 DB의 `SELECT FOR UPDATE SKIP LOCKED` 쿼리만으로 안전하고 충돌 없는 멀티 워커 큐 시스템을 직접 구현했습니다.
* **결함 허용성 (Fault Tolerance) 및 멱등성**
  * 파이프라인이 수천 장을 처리하다가 중간에 `kill -9`로 프로세스가 죽어도, Sweeper가 시체를 찾아내어 처음부터가 아닌 **"멈춘 곳부터"** 다시 시작(멱등성 보장)합니다. 
  * 인위적인 장애(Primary DB 다운) 상황에서도 Patroni 기반 Failover 후 시스템이 멈추지 않고 스스로 복구하는 **엔터프라이즈급 안정성**을 보여줍니다.

## 3. 최신 기술에 대한 깊은 이해 (Modern AI & MCP)

* **프롬프트 엔지니어링을 넘어서는 Agentic AI**
  * 챗봇 껍데기만 만드는 것이 아니라, 최신 글로벌 표준인 **MCP(Model Context Protocol)** 서버를 직접 구현합니다.
  * 이는 사용자가 AI에게 일일이 떠먹여 주는 방식이 아니라, AI가 우리 시스템의 `search_documents`, `get_chunk` 도구를 스스로 판단하고 호출하여 원하는 데이터를 채굴해오는 진정한 **Agent** 시스템임을 어필합니다.
* **pgvector와 HNSW 최적화**
  * 단순한 코사인 유사도 연산이 아니라, 수백만 건에서도 빠른 응답을 내는 `HNSW` 인덱스를 생성하고, EXPLAIN ANALYZE로 실행 계획까지 최적화하여 쿼리 퍼포먼스에 대한 깊이를 보여줍니다.

## 4. 발표 / 데모 구성 팁 (How to Show Off)

1. **장애 유발(Chaos Test) 퍼포먼스**: 
   데모 중 심사위원 앞에서 터미널을 열고 파이프라인 프로세스를 대놓고 죽이거나 네트워크를 잠시 끊어보십시오. 그리고 스위퍼가 어떻게 복구하고 시스템이 작업을 완수하는지 보여주면 기술 점수를 휩쓸 수 있습니다.
2. **AI의 자율성 보여주기**: 
   Claude 채팅창에서 로그 화면을 옆에 띄워두고, "이전 버전과 새 버전 규정의 차이점을 찾아줘"라고 질문하십시오. Claude가 혼자서 DB에 여러 번 쿼리를 날리며(MCP 도구 호출) 답을 조립해 나가는 **로그의 흐름**을 시각적으로 보여주는 것이 가장 큰 무기가 됩니다.

# Phase 7: 임베딩 배치 저장 및 파이프라인 통합 상세 (Developer B)

## 1. 개요
본 단계는 임베딩 API 클라이언트로부터 생성되어 반환된 대량의 고차원 벡터 데이터를 데이터베이스에 빠르고 안전하게 저장하는 과정을 담당합니다. 파이프라인 워커의 병목 현상을 줄이고 저장 정합성을 확보하는 데 중점을 둡니다.

## 2. 세부 구현 목표

### 2.1. 다중 데이터 배치 삽입 (Bulk Insert)
- **로직 구현 (`src/search/engine.py` 또는 `src/common/db.py`)**:
  - Ollama에서 반환받은 1024차원 배열을 `doc_search.embeddings` 테이블에 배치로 저장합니다.
  - Python 환경에서는 `psycopg2`의 `execute_values` 혹은 `asyncpg`의 `executemany` 등 데이터베이스 드라이버가 제공하는 벌크(Bulk) 저장 최적화 함수를 활용합니다.
- **상태 동시 업데이트**:
  - 벡터가 성공적으로 테이블에 삽입되면, 해당 벡터와 연관된 원본 `chunks` 레코드들의 `is_embedded` 값을 일괄적으로 `TRUE`로 업데이트합니다.

### 2.2. 트랜잭션 정합성 (ACID)
- **안전한 블록 처리**: 
  - 위의 배치 삽입 및 상태 업데이트 로직은 반드시 하나의 `BEGIN` / `COMMIT` 블록 안에서 처리되어야 합니다.
  - 저장 중 서버 프로세스가 강제로 죽거나 DB와의 연결이 끊겼을 때, 벡터 데이터가 절반만 들어가거나 상태 값이 일치하지 않는 현상을 원천적으로 차단합니다. 에러가 나면 트랜잭션이 전체 롤백(Rollback)되어야 합니다.

## 3. 협업 및 통합 사항
- 이 모듈은 Developer A가 개발하는 비동기 워커 데몬과 연결되어 동작하게 됩니다. 배치가 정상적으로 완료된 후 변경된 청크 카운트는 `activate_version()` 호출 검증의 중요한 판단 근거가 됩니다.

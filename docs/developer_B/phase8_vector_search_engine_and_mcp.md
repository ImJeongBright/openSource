# Phase 8: 벡터 검색 엔진 및 MCP 서버 완성 상세

## 1. 개요
이 단계는 본 프로젝트의 가장 핵심적인 목표로, AI 에이전트(LLM)가 우리 시스템에 축적된 기업 문서를 스스로 탐색하고 그 내용을 활용할 수 있도록 권한과 인터페이스를 부여하는 과정입니다. pgvector를 이용한 고성능 벡터 검색과 표준 MCP 인터페이스 구현이 주된 작업입니다.

## 2. 세부 구현 목표

### 2.1. 벡터 검색 엔진 최적화 (`src/search/engine.py`)

#### 하이브리드 서치 로직 구현
- **유사도 쿼리**: `pgvector`가 제공하는 코사인 유사도 연산자(`<=>`)를 활용하여 입력된 검색 벡터와 데이터베이스에 저장된 청크 벡터 간의 거리 기반 정렬 쿼리를 작성합니다.
- **메타데이터 필터링**: 단순히 벡터 거리만 계산하는 것을 넘어, 사용자가 특정 버전, 특정 문서 ID, 또는 날짜 필터 등을 요구할 경우 이를 `WHERE` 절에 결합하는 하이브리드 검색 기능을 구현합니다.
- **ACTIVE 버전 강제**: 쿼리 작성 시 어플리케이션 코드가 아닌 SQL 조인 레벨에서 무조건 `status = 'ACTIVE'` 인 문서 버전의 청크만 조회되도록 강제하는 제약사항을 포함시킵니다.

#### 실행 속도 모니터링 및 튜닝
- **HNSW 인덱스 점검**: `EXPLAIN ANALYZE` 쿼리를 실행하여, 실제로 벡터 검색 쿼리가 전체 순차 스캔(Seq Scan)을 하지 않고 생성해둔 HNSW 인덱스를 타는지 확인하고 모니터링합니다. 
- 파라미터(`m`, `ef_construction` 등)에 대한 튜닝 포인트를 정리해 둡니다.

### 2.2. MCP 서버 연동 (`mcp/server.py`)

#### 4가지 핵심 MCP 도구(Tool) 구현
Model Context Protocol(MCP) 스펙을 준수하는 서버 인터페이스를 개발하고, AI 모델이 시스템의 정보를 다룰 수 있도록 4개의 명확한 툴을 오픈합니다:
1. **`search_documents`**: 사용자의 텍스트 질문을 자체적으로 벡터 임베딩한 뒤, 2.1에서 만든 검색 엔진에 질의하여 시맨틱 기반의 Top-K 관련 텍스트 청크와 식별 메타데이터를 반환합니다.
2. **`get_document`**: 특정 문서 ID를 받아 해당 문서의 메타데이터(버전 정보, 생성일 등)를 반환합니다.
3. **`list_documents`**: 현재 시스템에서 검색 가능한 (`ACTIVE`) 문서들의 리스트를 반환하며, 페이지네이션을 지원합니다.
4. **`get_chunk`**: `search_documents` 결과에서 확인한 특정 위치의 원문을 더 자세히 확인하기 위해 청크 단위로 전문과 출처 정보를 제공합니다.

#### 출력 템플릿과 Traceability(추적성) 강제
- `search_documents` 및 `get_chunk` 툴이 데이터를 반환할 때는 반드시 `문서 제목`, `버전 번호`, `페이지 번호`, `섹션 제목` 등의 출처 추적성 정보를 포함하도록 JSON 포맷을 규격화합니다.

#### Claude Desktop 연동 테스트
- 개발한 `mcp/server.py`를 표준 입출력(stdio) 기반으로 구동되도록 설정하고, 실제 Claude 데스크탑 애플리케이션의 설정(config) 파일에 연결해 봅니다.
- 채팅창을 통해 에이전트가 툴을 잘 인식하고 호출하는지 종단간(End-to-End) 테스트를 수행합니다.

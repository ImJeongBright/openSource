# 유스케이스 명세서 (Use Case Specification)

**프로젝트명**: OpenSQL 기반 AI 문서 검색 및 버전 관리 시스템  
**문서 버전**: v1.0  
**작성일**: 2026-08-05

---

## 1. 액터 (Actors)

| 액터 | 유형 | 설명 |
|------|------|------|
| **문서 관리자** | 주 액터 (Human) | 문서 업로드, 삭제, 버전 확인을 수행하는 담당자 |
| **AI 서비스** | 주 액터 (System) | MCP 인터페이스를 통해 검색 기능을 호출하는 외부 AI 시스템 |
| **파이프라인 Worker** | 보조 액터 (System) | 문서 처리(추출, 청킹, 임베딩)를 비동기로 수행하는 내부 프로세스 |
| **Ollama 임베딩 서비스** | 자체 관리 시스템 | Qwen3 Embedding으로 텍스트를 벡터화하는 로컬 서비스 |
| **OpenSQL DB** | 외부 액터 (System) | 모든 데이터를 영구 저장하는 데이터베이스 |

## 3. 유스케이스 상세 명세

---

### UC-01: 문서 업로드

**개요**: 문서 관리자가 새로운 문서(PDF/TXT/Markdown)를 시스템에 업로드한다.

**주 액터**: 문서 관리자  
**보조 액터**: 파이프라인 Worker, 임베딩 API, OpenSQL DB

**사전 조건**:
- 문서 관리자가 시스템에 접근 가능한 상태여야 한다.
- 업로드 파일 형식이 PDF, TXT, Markdown 중 하나여야 한다.
- 파일 크기가 100MB 이하여야 한다.

**사후 조건 (성공)**:
- 문서 메타데이터가 DB에 저장된다.
- 변경 로그에 처리 대기 항목이 생성된다.
- 파이프라인이 비동기로 텍스트 추출 → 청킹 → 임베딩 처리를 수행한다.
- 모든 청크의 임베딩 완료 후 해당 버전이 검색 대상으로 활성화된다.

**사후 조건 (실패)**:
- 실패 사유가 변경 로그에 기록된다.
- 기존 활성 버전이 유지된다.

**기본 흐름**:
```
1. 문서 관리자가 파일과 메타데이터(제목, 카테고리 등)를 시스템에 전송한다.
2. 시스템이 파일 형식과 크기를 검증한다.
3. 시스템이 문서 레코드(상태: PENDING)를 DB에 생성한다.
4. 시스템이 변경 로그에 UPLOAD 이벤트를 기록한다.
5. 파이프라인 Worker가 변경 로그를 감지하고 처리를 시작한다.
6. Worker가 파일에서 텍스트를 추출한다. (페이지/섹션 정보 포함)
7. Worker가 텍스트를 청크로 분할하고 DB에 저장한다.
8. Worker가 각 청크에 대해 임베딩 API를 호출하고 벡터를 DB에 저장한다.
9. 전체 청크 임베딩 완료 후, 시스템이 해당 버전을 ACTIVE로 전환한다.
10. 시스템이 변경 로그를 COMPLETED로 업데이트한다.
```

**대안 흐름**:
- **2a. 파일 형식 불일치**: 오류 메시지 반환, 처리 중단.
- **8a. 임베딩 API 호출 실패**: 해당 청크를 FAILED로 표시, 변경 로그 유지 → UC-07 재시도.
- **8b. DB 저장 실패**: 트랜잭션 롤백, 변경 로그 유지 → UC-07 재시도.

### UC-02: 문서 버전 갱신

**개요**: 문서 관리자가 기존 문서의 수정본을 업로드하여 새 버전을 생성한다.

**주 액터**: 문서 관리자  
**보조 액터**: 파이프라인 Worker, 임베딩 API, OpenSQL DB

**사전 조건**:
- 업데이트 대상 문서가 시스템에 이미 존재해야 한다.
- 현재 ACTIVE 버전이 존재해야 한다.

**사후 조건 (성공)**:
- 새 버전의 모든 청크 임베딩이 완료된 후 ACTIVE 버전이 새 버전으로 원자적으로 전환된다.
- 이전 버전은 ARCHIVED 상태로 보존된다.

**기본 흐름**:
```
1. 문서 관리자가 기존 문서 ID와 새 파일을 함께 전송한다.
2. 시스템이 기존 문서의 최신 버전 번호를 조회한다.
3. 시스템이 새 버전 레코드(상태: PENDING)를 생성한다.
4. UC-01의 5~8 단계와 동일하게 처리한다.
5. 모든 임베딩 완료 후, 시스템이 단일 트랜잭션으로 다음을 수행한다:
   a. 기존 ACTIVE 버전을 ARCHIVED로 변경
   b. 새 버전을 ACTIVE로 변경
6. 변경 로그를 COMPLETED로 업데이트한다.
```

**대안 흐름**:
- **5a. 전환 중 트랜잭션 실패**: 롤백, 기존 ACTIVE 버전 유지, 변경 로그 FAILED로 기록.

---

### UC-03: 문서 삭제

**개요**: 문서 관리자가 문서를 시스템에서 제거한다.

**기본 흐름**:
```
1. 문서 관리자가 삭제 대상 문서 ID를 지정한다.
2. 시스템이 해당 문서의 모든 버전, 청크, 임베딩 벡터를 삭제한다.
3. 변경 로그에 DELETE 이벤트를 기록한다.
4. 시스템이 삭제 완료를 반환한다.
```

---

### UC-04: 문서 목록 조회

**개요**: 시스템에 저장된 문서 목록을 조회한다.

**기본 흐름**:
```
1. 액터가 필터 조건(카테고리, 날짜 범위, 상태 등)을 선택적으로 지정한다.
2. 시스템이 ACTIVE 버전이 존재하는 문서 목록을 반환한다.
3. 결과에는 문서명, 최신 버전, 마지막 업데이트 일시, 처리 상태가 포함된다.
```

---

### UC-05: 문서 의미 검색

**개요**: AI 서비스가 자연어 질의를 통해 관련 문서 청크를 검색한다.

**주 액터**: AI 서비스  
**보조 액터**: 임베딩 API, OpenSQL DB

**사전 조건**:
- 최소 1개 이상의 ACTIVE 버전 문서가 존재해야 한다.

**기본 흐름**:
```
1. AI 서비스가 MCP search_documents 도구를 호출한다.
   - 입력: 질의 텍스트, 결과 수(top_k), 필터 조건(선택)
2. 시스템이 질의 텍스트를 임베딩 API로 벡터화한다.
3. 시스템이 pgvector를 이용해 ACTIVE 버전 청크와 코사인 유사도를 계산한다.
4. 시스템이 상위 top_k 청크를 반환한다.
   - 출력: 청크 텍스트, 문서명, 버전, 페이지, 유사도 점수
```

---

### UC-06: 검색 결과 근거 확인

**개요**: AI 서비스가 특정 검색 결과의 원본 문서 위치를 확인한다.

**기본 흐름**:
```
1. AI 서비스가 청크 ID 또는 검색 결과 항목을 기반으로 상세 조회를 요청한다.
2. 시스템이 해당 청크의 원본 문서명, 버전, 페이지 번호, 섹션 제목, 전체 문단 텍스트를 반환한다.
```

---

### UC-07: 실패 작업 재시도

**개요**: 파이프라인 Worker가 장애로 미처리된 작업을 변경 로그 기반으로 재처리한다.

**주 액터**: 파이프라인 Worker

**사전 조건**:
- 변경 로그에 PENDING 또는 FAILED 상태의 항목이 존재한다.

**기본 흐름**:
```
1. Worker가 주기적으로 변경 로그에서 PENDING/FAILED 항목을 조회한다.
2. Worker가 해당 항목의 처리 단계를 확인한다 (추출/청킹/임베딩/전환 중 어느 단계에서 실패했는지).
3. 실패 단계부터 처리를 재개한다. (이미 완료된 청크는 건너뜀 - 멱등성 보장)
4. 최대 재시도 횟수 초과 시 DEAD_LETTER 상태로 전환하고 알림을 발송한다.
```

---

### UC-08: 임베딩 인덱스 재구축

**개요**: DBA가 pgvector 인덱스 손상 또는 설정 변경 시 저장된 임베딩 데이터를 기반으로 인덱스를 재구축한다.

**기본 흐름**:
```
1. DBA가 인덱스 재구축 명령을 실행한다.
2. 시스템이 기존 인덱스를 DROP한다.
3. 시스템이 DB에 저장된 임베딩 벡터를 기반으로 새 인덱스를 생성한다.
4. 재구축 완료 후 정상 서비스를 재개한다.
```

---

### UC-09: 버전 이력 조회

**개요**: 문서 관리자가 특정 문서의 전체 버전 이력을 조회한다.

**기본 흐름**:
```
1. 문서 관리자가 문서 ID를 지정한다.
2. 시스템이 해당 문서의 모든 버전 목록을 반환한다.
   - 출력: 버전 번호, 생성 일시, 상태(ACTIVE/ARCHIVED), 청크 수, 처리 소요 시간
```

## 4. 유스케이스 관계도

```
문서 관리자
    ├── UC-01 문서 업로드
    │       └── <<include>> UC-07 실패 작업 재시도 (실패 시)
    ├── UC-02 문서 버전 갱신
    │       └── <<extend>> UC-01 문서 업로드
    ├── UC-03 문서 삭제
    ├── UC-04 문서 목록 조회
    └── UC-09 버전 이력 조회

AI 서비스
    ├── UC-05 문서 의미 검색
    │       └── <<include>> UC-06 검색 결과 근거 확인
    └── UC-04 문서 목록 조회

인프라/DBA
    └── UC-08 임베딩 인덱스 재구축

파이프라인 Worker
    └── UC-07 실패 작업 재시도 (자동 실행)
```

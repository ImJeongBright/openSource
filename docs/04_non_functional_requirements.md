# 비기능 요구사항 명세서 (Non-Functional Requirements Specification)

**프로젝트명**: OpenSQL 기반 AI 문서 검색 및 버전 관리 시스템  
**문서 버전**: v1.0  
**작성일**: 2026-08-05

---

## 1. 성능 (Performance)

### NFR-PERF-01: 검색 응답 시간
- 의미 검색(pgvector 쿼리) 응답 시간은 p95 기준 500ms 이하이어야 한다.
- top_k = 5 기준, 문서 10만 청크 이하 환경에서 측정한다.

### NFR-PERF-02: 임베딩 처리 처리량
- 파이프라인 Worker는 분당 최소 500개 청크의 임베딩을 처리할 수 있어야 한다. (외부 임베딩 API 속도에 의존)

### NFR-PERF-03: 동시 검색 처리
- 동시 검색 요청 50건을 처리하는 상황에서도 NFR-PERF-01 기준을 충족해야 한다.

### NFR-PERF-04: 문서 업로드 접수 시간
- 파일 수신 및 DB 등록(변경 로그 생성까지) 시간은 5초 이내이어야 한다. (실제 처리는 비동기)

---

## 2. 가용성 (Availability)

### NFR-AVAIL-01: 서비스 가용성
- MCP 검색 서비스의 목표 가용성은 99.9% (월 기준 약 43.8분 다운타임 허용)이다.

### NFR-AVAIL-02: DB 고가용성
- OpenSQL Patroni HA 구성을 통해 Primary 노드 장애 발생 시 30초 이내에 자동 Failover가 완료되어야 한다.
- Failover 기간 중 진행 중이던 쓰기 트랜잭션은 변경 로그를 통해 재처리될 수 있어야 한다.

### NFR-AVAIL-03: Worker 가용성
- 파이프라인 Worker 프로세스가 비정상 종료 시 자동으로 재시작되어야 한다. (systemd 또는 프로세스 관리자 사용)
- 재시작 후 변경 로그를 기반으로 미처리 작업을 자동으로 재개해야 한다.

---

## 3. 신뢰성 및 데이터 정합성 (Reliability & Consistency)

### NFR-REL-01: 버전 정합성
- 검색 결과에 ACTIVE가 아닌 버전의 청크가 포함되어서는 안 된다.
- 새 버전으로의 전환은 원자적으로 수행되어야 하며, 전환 중간 상태가 외부에 노출되어서는 안 된다.

### NFR-REL-02: 데이터 유실 방지
- 임베딩 처리 실패 시 데이터 유실 없이 변경 로그를 기반으로 100% 복구 가능해야 한다.
- 이미 임베딩이 완료된 청크는 재처리 시 덮어쓰지 않아야 한다. (멱등성)

### NFR-REL-03: 중복 처리 방지
- 동일한 변경 로그 항목이 둘 이상의 Worker에 의해 동시에 처리되지 않도록 보장해야 한다.
- `SELECT FOR UPDATE SKIP LOCKED` 패턴을 사용하여 분산 락을 구현한다.

---

## 4. 확장성 (Scalability)

### NFR-SCALE-01: 문서 규모 확장
- 시스템은 문서 10만 건, 청크 500만 개, 임베딩 벡터 500만 개까지 성능 저하 없이 운영 가능해야 한다.

### NFR-SCALE-02: Worker 수평 확장
- 파이프라인 Worker를 여러 인스턴스로 수평 확장할 수 있어야 한다.
- Worker 인스턴스 추가 시 변경 로그 기반 작업 분배가 자동으로 이루어져야 한다.

### NFR-SCALE-03: 임베딩 모델 교체
- 임베딩 모델 교체 시 기존 데이터의 재처리가 가능해야 한다.
- 재처리 중에도 기존 ACTIVE 버전의 검색 서비스는 계속 제공되어야 한다.

---

## 5. 보안 (Security)

### NFR-SEC-01: 임베딩 API 키 관리
- 임베딩 API 키는 환경변수 또는 별도 시크릿 관리 도구(Vault 등)를 통해 관리되어야 한다.
- 소스 코드 또는 설정 파일에 API 키를 평문으로 저장해서는 안 된다.

### NFR-SEC-02: DB 접근 제어
- OpenSQL DB 접근은 애플리케이션 전용 계정을 사용하고, 최소 권한 원칙을 적용해야 한다.
- MCP 서버와 파이프라인 Worker는 각각 별도 DB 계정을 사용해야 한다.

### NFR-SEC-03: MCP 통신 보안
- MCP 서버와 AI 서비스 간의 통신은 TLS로 암호화되어야 한다. (운영 환경 기준)

### NFR-SEC-04: 문서 원본 파일 보안
- 업로드된 원본 파일은 처리 완료 후 서버에 보관하지 않거나, 접근 제어된 스토리지에 별도 보관한다.

---

## 6. 유지보수성 (Maintainability)

### NFR-MAINT-01: 로깅
- 파이프라인의 모든 단계(업로드 수신, 추출, 청킹, 임베딩, 전환)에서 구조화된 로그(JSON 형식)를 출력해야 한다.
- 로그에는 문서 ID, 버전 번호, 타임스탬프, 소요 시간, 오류 코드가 포함되어야 한다.

### NFR-MAINT-02: 처리 상태 모니터링
- 변경 로그 테이블을 조회하여 현재 처리 대기/진행/완료/실패 건수를 확인할 수 있어야 한다.
- 운영자가 특정 문서의 처리 진행 상황을 실시간으로 추적할 수 있어야 한다.

### NFR-MAINT-03: 설정 관리
- 청킹 파라미터(chunk_size, overlap), 임베딩 모델명, 재시도 횟수 등은 코드 수정 없이 설정 파일로 변경할 수 있어야 한다.

### NFR-MAINT-04: 인덱스 관리 스크립트
- pgvector 인덱스 재구축을 위한 관리 스크립트가 제공되어야 한다.
- 인덱스 타입(HNSW / IVFFlat) 및 파라미터를 변경하여 재구축할 수 있어야 한다.

---

## 7. 이식성 (Portability)

### NFR-PORT-01: 운영 환경
- 시스템은 Rocky Linux 9.7 환경에서 동작해야 한다.
- 파이프라인 및 MCP 서버는 Python 3.10 이상에서 동작해야 한다.

### NFR-PORT-02: DB 표준 호환성
- 시스템은 PostgreSQL 17.x 표준 SQL 및 pgvector 확장 기능만을 사용해야 한다.
- 특정 클라우드 DB 서비스에 의존하는 기능을 사용해서는 안 된다.
